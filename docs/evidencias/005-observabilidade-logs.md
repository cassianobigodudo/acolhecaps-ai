\"trace-20240915-a7b8c9d0e1f2g3h4\" logs/observability.jsonl | wc -l\n# Output: 16 eventos\n\n# Exemplo 2: Extrair apenas os nomes dos nodes\ngrep \"trace-20240915-a7b8c9d0e1f2g3h4\" Output: 5829\n\n# Exemplo 4: Prioridade final\ngrep \"trace-20240915-a7b8c9d0e1f2g3h4\" logs/observability.jsonl \\\n  | grep \"END\" | jq '.metadata.prioridade_final'\n# Output: Observabilidade**:\n```bash\ngrep \"trace-20240915-xyz\" logs/observability.jsonl \\\n  | jq 'select(.metadata.elapsed_ms > 5000)' \\\n  | jq '{node: .metadata.node, elapsed_ms: .metadata.elapsed_ms}'\n\n# Output:\n# {\"node\": \"node_human_in_the_loop\", \"elapsed_ms\": 10500}\n\n# Conclusão: HITL aguardando aprovação, não é defeito de código\n```\n\n### Caso 2: Auditoria de Decisão Clínica\n\n**Pergunta**: Por que este paciente foi classificado como \"Alta\" prioridade?\n\n**Resposta via Logs**:\n```bash\ngrep \"trace-xyz\" logs/observability.jsonl | jq '.message, .metadata'\n\n# Output:\n# [\"[EVENT] node_rag_diretrizes: concluido\", {diretrizes_recuperadas: 3, top_score: 0.98, top_titulo: \"Ideação Suicida Ativa\"}]\n# [\"[EVENT] node_avaliacao_risco: concluido\", {prioridade: \"Alta\", motivo: \"Ideação suicida com planejamento\"}]\n# [\"[DECISION] Roteamento para HITL\", {decisao: \"para_hitl\"}]\n\n# Conclusão: RAG recuperou \"Ideação Suicida Ativa\" → LLM classificou Alta → HITL acionado\n```\n\n### Caso 3: Detecção de Anomalia\n\n**Observação**: Muitos traces com latência > 10 segundos nos últimos 30 minutos\n\n**Ação com Observabilidade**:\n```bash\n# Buscar traces com tempo total > 10s nos últimos 30 min\njq 'select(.timestamp > \"2024-09-15T10:00:00Z\" and \n           .metadata.tempo_total_ms > 10000)' \\\n  logs/observability.jsonl | \\\n  jq -s 'group_by(.metadata | select(.elapsed_ms)) | \n         map({node: .[0].metadata.node, count: length, avg_ms: \n              (map(.metadata.elapsed_ms) | add / length)})'\n\n# Output mostra qual node está causando atrasos\n```\n\n---\n\n## 📊 Estrutura do Log JSON\n\n### Campos Obrigatórios\n\n```json\n{\n  \"timestamp\": \"ISO8601 timestamp\",\n  \"level\": \"INFO|WARN|ERROR|DEBUG\",\n  \"message\": \"Descrição do evento\",\n  \"trace_id\": \"trace-YYYYMMDD-XXXXXXXX\",\n  \"metadata\": {\n    \"node\": \"node_name\",\n    \"action\": \"started|completed|failed\",\n    \"elapsed_ms\": 123\n  }\n}\n```\n\n### Campos Opcionais (Context-Dependent)\n\n```json\n{\n  \"metadata\": {\n    \"id_paciente\": \"PAC-2024-001\",\n    \"cep\": \"88015-100\",\n    \"prioridade\": \"Alta\",\n    \"diretrizes_recuperadas\": 3,\n    \"top_score\": 0.98,\n    \"status_aprovacao\": \"aprovado\",\n    \"erro\": \"error message se houver\"\n  }\n}\n```\n\n---\n\n## ✅ Conformidade com Avaliação\n\n✅ **2 Sinais de Observabilidade Correlacionados:**\n1. **Logs Estruturados em JSON** ✅\n   - Cada log é um objeto JSON\n   - Contém timestamp, level, message, trace_id, metadata\n   - Arquivo: `logs/observability.jsonl`\n\n2. **Trace_id Correlacionado** ✅\n   - Gerado automaticamente por requisição\n   - Injetado em todos os nodes\n   - Permite rastrear caminho completo\n   - Formato: trace-YYYYMMDD-XXXXXXXX\n\n✅ **Rastreabilidade**:\n- Erros: Registrados com timestamp e trace_id\n- Latência: Capturada em cada node\n- Decisões: Logged com motivo\n- Aprovações: Logged com aprovador e timestamp\n\n✅ **Sem Exposição de Dados Sensíveis**:\n- ID do paciente (genérico): PAC-XXXX\n- Relato: Nunca logado\n- CEP: Logado apenas para auditoria\n- Dados clínicos: Apenas prioridade final\n\n---\n\n## 🎯 Próximas Análises\n\n1. **Agregação**: Consolidar logs em ElasticSearch/Splunk\n2. **Dashboard**: Visualizar traces em tempo
